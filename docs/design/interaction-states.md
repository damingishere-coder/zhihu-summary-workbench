# 交互与状态

## 添加问题

1. 点击“添加知乎问题”打开模态框，焦点进入链接字段。
2. 链接必须是 `https://www.zhihu.com/question/{数字}` 或 `https://zhihu.com/question/{数字}`。
3. 标题为空时允许后端从链接生成临时标题，但 UI 会提示建议填写。
4. 示例回答用于第一阶段验证观点提取；为空时使用问题描述。
5. 成功后关闭弹窗、刷新问题池并显示“已保存到问题池”。
6. 重复链接保留弹窗并提示已存在问题，不清空用户输入。

## 批量导入

- 一行一个链接，空行忽略。
- 提交中禁用关闭和重复提交。
- 返回新增、重复和失败数量；部分成功不显示为完全失败。
- 不自动将所有导入项加入任务，避免意外消耗模型配额。

## 入队与实时进度

- 入队后立即显示 `queued`，不等待 Worker 开始。
- SSE 在线显示绿色“实时更新”；重连显示蓝色“正在重连”；离线显示红色并提供手动刷新。
- 进度阶段至少为：排队、准备输入、观点提取、保存结果、待审核。
- 收到事件后只刷新相关查询，避免整页闪烁。
- 任务完成后展示分析结果和草稿入口。

## 重试、取消、忽略和删除

- 重试只对 `failed` 或 `cancelled` 开放；保留旧日志和重试次数。
- 取消只对 `queued` 或运行中任务开放，必须二次确认。
- 忽略问题是可逆状态更新，不删除数据。
- 删除问题是危险操作，必须二次确认并说明关联任务和版本会受约束保护。
- 禁用按钮必须通过 Tooltip 说明原因。

## 页面通用状态

### 加载

- 首屏用骨架保留最终结构。
- 按钮使用局部 loading，不遮挡整个页面。

### 空

- 问题池为空：解释用途并提供“添加知乎问题”。
- 任务为空：提示先在问题池加入任务。
- 草稿为空：说明完成结构化分析后自动产生最小草稿。

### 错误

- 页面级错误显示错误原因、影响范围和“重新加载”。
- 行级错误显示在对应任务，完整堆栈只进入日志。
- Redis 断开时添加问题仍可保存，但入队明确失败并可重试。

### 禁用

- 不能执行的原因在控件附近可见。
- 未配置 DeepSeek 密钥时，真实模式测试按钮禁用；Mock 模式仍可测试。

### 成功

- 创建、保存和入队使用简短消息。
- 长任务成功不弹阻断式模态框，通过状态和时间线更新。

## 暗色模式

- 主题切换即时生效并保存到本地偏好。
- 表格、弹窗、代码/日志区、状态标签和焦点环都使用暗色 Token。
- 不通过简单反色生成暗色主题。

## 响应式

- 1440×900：完整侧栏、表格和右侧日志。
- 1280×720：隐藏次要列，右侧日志缩窄或改为抽屉；主操作始终可见。
- 短视口下内容区独立滚动，侧栏和顶栏不遮挡底部操作。

## 键盘与焦点

- `Tab` 顺序与视觉顺序一致。
- 模态框关闭后焦点回到触发按钮。
- 危险确认默认焦点不放在确认按钮。
- 路由切换后聚焦页面标题。

## 第三阶段信息图

1. “生成信息图内容”创建一个新版本，不覆盖图片 Prompt 或上传历史。
2. 打开编辑器后，标题、结论、观点、模板、字号、品牌和页脚修改实时进入预览。
3. 拖拽观点只调整当前编辑副本；点击“保存新版本”后才写入数据库。
4. 字段超长时立即提示；后端渲染仍会进行 DOM 溢出检查，前端检查不能替代最终检查。
5. 渲染期间禁用重复提交；失败时保留 HTML 快照和日志入口。
6. 下载按钮只在 PNG 实际存在时可用。
7. 历史版本可查看和恢复；恢复会创建新版本，不删除当前版本。
8. 背景删除后自动切到纯 CSS；没有背景图不阻塞渲染。

## 第三阶段排期与发布

1. 只有已人工审核文章可以加入发布队列。
2. 创建排期时固定文章和图片版本；后续编辑不会静默改变已排期内容。
3. 同一天超出每日上限、时间间隔不足或同一草稿重复排期时显示冲突并阻止保存。
4. 日历拖拽改期复用同一冲突校验；失败时事件回到原日期。
5. 执行前必须输入“确认发布”；默认只生成手动发布包。
6. 辅助发布先检查浏览器目录、登录、验证码、正文和图片，任何一项不通过就保存暂停记录。
7. 登录失效和验证码不是普通失败，不自动重试，也不尝试绕过。
8. 自动发布开关默认关闭；打开开关不会跳过文章审核和发布前确认。

## Prompt 与预算

- 生产 Prompt 默认只读；编辑操作创建草稿副本。
- 测试结果与生产版本分开保存，测试失败不影响当前启用版本。
- 启用新版本和回滚旧版本都需要二次确认并记录审计日志。
- 预算达到 80% 显示预警；超预算时新的文本模型请求暂停，缓存命中仍可返回。
- 修改预算或模型只影响后续调用，不回算历史费用。
