# 当前开发路线与真实状态

更新时间：2026-09-07

内容流水线基线分支：`codex/zhihu-production-workflow-20260907`。2026-09-08 UI 改版使用独立分支 `codex/zhihu-creative-ui-20260907`，页面变化与验证边界见 [UI 改版记录](ui-redesign.md)。本文件记录当前状态，旧 phase 文档保留为历史快照。

## 本次实现

- RunDock 托管原有两个组件：后端 8002、前端 4173；手动启动，无定时启动、无自动重启。后端以前台 runtime 运行，迁移前备份 SQLite。
- 首页手动执行/继续/暂停今日计划，默认 10 题；热榜与手动候选互补，显示安排、文章、图文、等待、失败与缺口。启动服务不生产，重启后的未完任务等待用户继续。
- 扩展 0.3.0 读取热榜和问题 DOM；每批持久确认、按回答 ID 去重、累计可超过 500 条；每题最多 30 分钟。未确认读完时明确标注覆盖范围，资料不足允许人工选择按现有样本继续。
- 长回答分段分析，保留尾部内容；检查缺失/重复来源。观点逐条参与语义分组，来源标注支持、反对、条件或相关，不把来源数量一律当支持票。
- 持久阶段检查点；采集来源变化会使分析检查点失效。文章版本冻结来源正文、哈希、观点及段落映射；迁移为旧版本保存当前可获得的来源快照。
- 独立审核不通过时最多自动修正一次，仍不通过则暂停等待人工处理。
- Codex CLI 内置生图、已有图片结果核对、中文 HTML/CSS 排版、自适应画布/字号与溢出阻断；支持人工替换背景。
- 发布包 ZIP 包含 Markdown、HTML、PNG、来源快照和版本/文件哈希清单。审核未通过或图文版本不一致时阻断。最后发布仍由用户在知乎完成。
- Codex 未报告的用量/费用标记为未知；不把额度计费显示成已知零成本。

## 手动使用顺序

1. RunDock 中启动“知乎工作台”，打开 `http://127.0.0.1:4173`。
2. Chrome 加载扩展 0.3.0，正常登录知乎，在工作台浏览器设置页配对。
3. 首页点击“执行 / 继续今日计划”；需要停止时点击“暂停计划”。遇登录/验证码由用户处理。
4. 检查草稿、来源、图片，审核通过后下载发布包，到知乎人工发布。
5. 不使用时在 RunDock 停止该项目。再次启动后，未完任务需点继续。

本次不部署云端、不改变 Codex 认证、不绕过平台验证、不自动合并 PR。
