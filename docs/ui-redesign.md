# 创作工作台 UI 改版

日期：2026-09-08。基于 `codex/zhihu-production-workflow-20260907`，独立分支 `codex/zhihu-creative-ui-20260907`。本次只交付本地工作台，不部署云端、不合并前置 PR。

## 主要页面对比

| 页面 | 改版前 | 改版后 |
| --- | --- | --- |
| 导航 | 七个并列入口，带运营组身份信息 | 今天、选题、作品三个主要入口，设置在底部；旧链接保留 |
| 首页 | 今日计划、重复指标、服务状态、任务表与常驻日志竞争空间 | 今日计划与明确的开始/继续操作；跨日期待办、待检查作品、生成进度；运行详情按需展开 |
| 选题 | 短标题列、图标操作、局部分页数据 | 可换行标题、文字操作、真实服务端分页；窄窗口优先保留标题与下一步 |
| 问题详情 | 回答、观点、费用日志同时挤在三栏 | 概览/回答/观点地图标签，任务和费用进入抽屉 |
| 作品列表 | 草稿表格与发布准备分散 | 作品摘要、待检查/已审核筛选，与导出页面共同归入作品 |
| 作品检查 | 文章、图片、质量报告三栏挤压正文 | 文章/配图/审核与导出三步；默认宽版阅读，来源侧栏，固定步骤操作区 |
| 发布准备 | 再次出现生产计划与模型统计 | 集中展示图文准备状态、下载、日历与记录；模型用量移至任务记录的折叠详情 |

## 数据与交互约定

- 业务后端、数据库、生成链路、浏览器扩展和认证保持现有实现。API 客户端的草稿列表新增可选分页参数，后端已支持 `offset` / `limit`。
- 聚合待办逐页读取完整列表，不用首页近期任务当总量。读取中出现分页数量不一致时显示重试提示。
- `step=article|image|review` 保存作品检查步骤；旧审核 URL 默认阅读文章。列表筛选、分页和返回地址通过 URL 保留；数据路由恢复滚动位置。
- 目标题数先编辑再保存；打开页面、切换步骤不会启动采集、模型调用或人工审核。
- 文章与图片本地修改不会被后台刷新覆盖；保存失败保留输入。离开作品、浏览器返回和关闭页面均有未保存保护。图片未保存时不能渲染或切换到其他已保存版本。
- 导出依赖后端准备检查，保留人工审核与版本匹配限制；下载不代表已经在知乎发布。旧文章没有完整覆盖记录时明确显示未知。

## 验证方式

- Vitest：实际组件配合模拟接口，覆盖手动执行/暂停、目标显式保存、分页聚合、异常对应操作、步骤保留内容、后台刷新、保存失败、离开与放弃、保存后离开、历史版本恢复确认、审核与导出，以及配图编辑保护。
- 浏览器：使用现有本地数据检查页面，覆盖 1440、1280、1024、768px、明暗主题。80 组页面与视口组合检查渲染和整页横向溢出；截图检查首页、选题、文章阅读和审核，验证键盘切换问题详情标签。
- 本机 42 项前端测试、4 项 Sites 契约测试通过，生产构建和类型检查通过；GitHub CI 另外运行后端与扩展回归。
- 浏览器验收未点击实际生成、采集、审核、上传或发布操作；写入流程由模拟接口测试覆盖，不替代真实五题采集与日产十篇验收。

## 保留的限制

- 当前生产构建仍有主 JS 包超过 500 kB 的提示；本次没有进行路由拆包或技术栈迁移。
- 主要适配电脑和窄窗口；本次不承诺手机上完整的专业编辑体验。
- 发布日历、提示词版本和浏览器设置保留原有业务行为，新的导航归组不改变实际执行权限。
