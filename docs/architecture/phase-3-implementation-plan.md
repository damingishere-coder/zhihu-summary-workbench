## 第三阶段缺口

| 规格能力 | 当前证据 | 结论 |
| --- | --- | --- |
| 信息图内容 JSON | 图片 Prompt 生成时有基础 JSON | 需要独立生成接口、严格长度约束和版本化编辑 |
| 两种信息图模板 | 尚无可渲染模板 | 需要知识总结卡、观点对比表 |
| 图片编辑器 | 只有 Prompt、上传与历史 | 需要标题、结论、观点排序、字体、品牌、页脚、裁切和溢出提示 |
| 1080×1440 PNG | `rendered_path` 未使用 | 需要 Playwright 渲染、HTML 快照、重试和下载 |
| 发布中心 | 只有阶段锁定占位 | 需要内容准备、日历排期、执行记录和冲突提醒 |
| 浏览器发布安全 | 只有采集器 | 需要会话管理、登录/验证码/页面异常暂停和人工确认 |
| 每日计划 | 只有基础表和设置 | 需要共用调度器、立即执行和 Worker 定时检查 |
| 成本控制 | 问题级总量已有 | 需要今日/问题/阶段统计、预算暂停、缓存和降级计数 |
| Prompt 管理 | 只有列表与版本读取 | 需要新增版本、启用、测试、回滚和审计 |
| 完整路由 | 缺 `/prompts`、浏览器和开源设置 | 需要补齐最终路由清单 |

## 数据库迁移

新增 revision：`20260724_0003`。

迁移原则：

- 只增加表、列和索引，不覆盖文章、图片、Prompt 或发布历史；
- 为已存在的 SQLite 数据库做存在性检查；
- 空数据库仍可按 `0001 → 0002 → 0003` 完整安装；
- 升级前备份本地数据库到 `data/backups/`；
- 上传原图、缩略图、HTML 快照、PNG 和发布截图继续放在 Git 忽略的 `data/` 中。

计划变更：

- 扩展 `daily_plans`：执行时间、并发、最大回答数、每日发布上限、间隔和自动开关；
- 扩展 `model_usage_logs`：阶段、缓存命中、降级和重试次数；
- 新增 `model_response_cache`，缓存结构化文本模型结果；
- 扩展 `prompt_versions`：参数、测试输入输出、变更说明和创建人；
- 扩展 `image_versions`：缩略图、HTML 快照、渲染状态、画布、溢出和渲染日志；
- 扩展 `publish_schedules`：文章/图片版本、顺序、间隔、确认和执行时间；
- 扩展 `publish_records`：最终文章/图片版本、截图和尝试次数。

## 后端实施

### 信息图

- 新增严格 Pydantic 信息图结构和文字长度限制；
- 使用统一文本 Provider 生成信息图 JSON，并记录 Token、费用、缓存和降级；
- 图片编辑保存为新版本，不覆盖历史；
- 上传原图时生成缩略图；
- 提供模板、编辑、恢复、渲染、批量渲染、下载和版本接口；
- Playwright 固定 1080×1440 或 1242×1660，等待字体和图片，检测溢出，失败重试并保存 HTML/日志。

### 发布与计划

- 实现内容准备、排期 CRUD、冲突检查和执行记录；
- 发布前必须传入人工确认，默认只生成手动发布包；
- 辅助发布先检查本地浏览器目录、登录、验证码和编辑器状态，遇到风险立即暂停；
- 不保存 Cookie、账号密码或浏览器缓存；
- 每日计划的立即执行和定时执行共用 `execute_daily_plan`。

### 成本与 Prompt

- 汇总今日、问题、阶段、模型、缓存、降级和手动图片次数；
- 每日预算为 0 时表示不限制，大于 0 且超额时暂停新的文本模型请求；
- Prompt 编辑始终创建新版本，启用或回滚单独记录审计；
- Prompt 测试不覆盖生产版本。
